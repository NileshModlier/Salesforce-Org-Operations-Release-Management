# L2 runbook

Second-line checks for automation, access, release, data, and reporting. The assistant does not change Salesforce, assign permissions, edit configuration, deploy, or activate a flow. A person follows the resolution. Every entry has a symptom, checks, a resolution, and escalation criteria.

## L2:Flow Faults

Keywords: flow fault

### Symptom

A lead or case did not move as the user expected, or a fault message names Lead Assignment, Case Assignment, First Response Tracking, or Escalation.

### Checks

1. Confirm the flow status in source. All four flows are Draft. A Draft flow does not run.
2. Confirm which outcome the design uses. OwnerNotFound and QueueNotFound are handled outcomes, not faults. A fault is an unexpected failure while reading or updating a record.
3. For Escalation, confirm the design refuses to update when the L2 queue is missing or no active user has Persona Ops Admin. That refusal avoids a save that would break the escalation validation rule.
4. Confirm First Response Tracking stamps First Response At only when the prior status was New, the new status is not New, and the field is empty.

### Resolution

1. If the flow is Draft, tell the user the owner will stay the creator. Do not activate the flow from this page.
2. If a fault is reported after a future activation, copy the fault message and the flow name. Do not edit the flow in the org.
3. Leave the record as saved. Do not run a second update to hide the message.

### Escalation Criteria

Escalate to Ops Admin when a flow is Active and was not activated under a release, or when a fault message appears. Ops Admin uses the release plan. This assistant does not deploy or activate anything.

## L2:Validation Rule Issues

Keywords: validation rule

### Symptom

A save fails and Salesforce shows one of the six project rule messages.

### Checks

1. Lead, email or phone: Enter an email address or a phone number before saving this lead. Mobile does not count.
2. Lead convert: Convert this lead only when its status is Qualified. The convert action writes Closed - Converted. The rule looks at the status from before that write.
3. Closed Won: Enter an amount greater than zero before setting the stage to Closed Won. Closed Lost and open stages are not blocked for a blank amount.
4. Escalated case: Enter the escalation reason and the agent who escalated before saving an escalated case.
5. Closed case: Enter resolution notes before closing this case.
6. Return to L1: Enter return guidance before sending an escalated case back to L1. This applies when the prior status was Escalated and the new status is New, Working, or Waiting on Customer.

### Resolution

1. Read the message to the user and name the field to fill.
2. Ask the user to enter that value and save again. Do not deactivate the rule.
3. L1 cannot edit Resolution Notes or Return Guidance. If the task is a close or a return, Support Lead L2 enters those fields. L2 still cannot delete the case.

### Escalation Criteria

Escalate to Ops Admin only when the message does not match one of the six rules above, or when the approved process itself needs a change. That change is a work item, not an in-org edit.

## L2:Permission Set Problems

Keywords: permission set group

### Symptom

A user can see the wrong objects, cannot run a report they should run, or was given setup access they should not have.

### Checks

1. Confirm the profile has no object permissions. Business access is on the permission set inside the group.
2. Confirm the group. Sales Rep contains Sales_Rep and Reporting_Sales. Support Agent L1 contains only Support_L1. Support Lead L2 contains Support_L2 and Reporting_Support. Ops Admin contains Ops_Admin and Reporting_Admin.
3. Confirm L1 has no Run Reports permission and no Transfer Cases permission. L2 has Transfer Cases and view-all cases, and no case delete. No set includes Modify All Data.
4. Confirm queue membership separately. The group does not add the user to Support_L1 or Support_L2.
5. Confirm User.Persona__c matches the story for Lightning. It is not the grant.

### Resolution

1. Tell the user which group matches the job. Do not assign it yourself unless you are the named Ops Admin.
2. Ops Admin assigns one group and sets Persona. Ops Admin does not grant Modify All Data to finish a ticket.
3. If an L1 user needs the team report, the answer is no. L2 runs that report.

### Escalation Criteria

Escalate to Ops Admin when the assigned group does not match this table. Support Lead L2 does not manage users, profiles, or permission sets.

## L2:Release Failures

Keywords: release failure

### Symptom

A promotion to Org B or Org A failed, a validation script failed after a deploy, or someone wants to skip UAT.

### Checks

1. Confirm which package it was. Release 1 is the operating process and access model. Release 2 is reports and dashboards and depends on Release 1.
2. Confirm the changelog outcome. Both releases are Not executed until a deploy id and commit SHA are written. Rollback status stays Not required until an org actually changed.
3. Confirm the path. Development is a scratch org. UAT is Org B. The production stand-in is Org A. There is no sandbox and no customer production org.
4. Confirm Flosum is Not Executed. A failed or missing Flosum login is not a release path.
5. Confirm whether Org B could be attached as a Lifecycle Center stage. That check has not been run. If it fails later, the same git commit is deployed with the CLI and the limitation is written down.

### Resolution

1. Stop the next stage. Do not merge to main and do not force push.
2. Record the commit SHA, the org alias, and the error text on the work item.
3. Re-run the validation script named on the work item. A skipped script is a failed promotion, not a reason to roll back.
4. Start the rollback drill only when a rollback criterion in the release plan is met. The drill is a tabletop until Ops Admin runs it. A normal deploy does not delete metadata. Removing Release 2 needs the destructive change list, and only after Org B accepts that removal.
5. Do not activate the four flows as part of recovering a failed deploy.

### Escalation Criteria

Escalate to Ops Admin for every release failure. Support Lead L2 does not approve production promotion and does not deploy.

## L2:Data Corrections

Keywords: data correction

### Symptom

A record has a wrong field value, or a load did not match the synthetic counts.

### Checks

1. Confirm who may edit the field. Sales Rep edits own leads and opportunities. L1 edits own or queue cases, except Resolution Notes and Return Guidance, which are read-only. L2 edits cases and does not delete them. Ops Admin can edit the project fields, including Persona.
2. Confirm the correction is a new value on the field the validation message names, not a delete of the row.
3. For a synthetic load, confirm the order in the reporting notes. Leads that should convert are inserted as Qualified and converted without creating an extra opportunity. Closed Won amounts are greater than zero. Escalated cases need a reason and a real user in Escalated By. The flows stay Draft during the load.
4. Confirm two CRM users cannot own five logical owner names at once. Closed-by-agent groupings follow the real owner.

### Resolution

1. Ask the person who is allowed to edit the field to enter the corrected value and save.
2. Do not mass-delete leads, cases, or opportunities to make a chart match.
3. Do not convert the ten target leads if that convert will also create opportunities on top of the 18-row opportunity file.
4. This assistant does not edit the record.

### Escalation Criteria

Escalate to Ops Admin when the correction needs a field the support user cannot edit, a delete, or a reload of the synthetic file.

## L2:Reporting Discrepancies

Keywords: reporting discrepancy

### Symptom

A dashboard number does not match what a manager expected from the synthetic notes.

### Checks

1. Confirm the dashboard has been rendered. The metric notes say the dashboard value was not observed, because no org was connected when those notes were written.
2. Confirm the comparison only after the synthetic load. Open opportunity amount for a user who can read every opportunity is 221000 across 13 open rows. Conversion rate after the ten conversions is 41.67 percent, which is 10 divided by 24. Open cases are 15. Escalated cases are 4. Average first response on the 16 stamped cases is 3.00 hours.
3. Confirm who is looking. Pipeline By Stage is the running user's own opportunities. A Sales Rep must not be compared with the full-book 221000. In the file, Rep A owns 165000 of open amount and Rep B owns 56000.
4. Confirm the month. Opportunities Closing This Month is the current calendar month. The 11 opportunities and 212000 amount are a November 2026 run.
5. Confirm L1 is not the person judging the team dashboard.

### Resolution

1. If the viewer, the load, or the month explains the gap, tell the user the expected figure for that situation. Do not edit the report.
2. If the viewer can read every row, the load is complete, the month matches, and the number still differs, record the report name, the filter, and both numbers.
3. Do not change a formula, a filter, or a dashboard component in the org to force the hand count.

### Escalation Criteria

Escalate to Ops Admin when the documented conditions are met and the number still differs. Ops Admin treats a report change as a work item.
