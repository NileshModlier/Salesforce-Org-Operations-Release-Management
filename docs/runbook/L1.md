# L1 runbook

First-line checks for access and case handling. The assistant does not change Salesforce. A person follows the resolution. Every entry has a symptom, checks, a resolution, and escalation criteria.

## L1:Login Problems

Keywords: cannot log in

### Symptom

A named user cannot log in to the Developer Edition org.

### Checks

1. Confirm the login host is https://login.salesforce.com. The sandbox host test.salesforce.com is not used. This project has no sandbox.
2. Confirm the username is that person's named user. Shared passwords are out of bounds.
3. Confirm the user is one of the two Salesforce CRM licenses, or a platform user that is actually assigned. Four personas are roles, not four simultaneous CRM logins.
4. Confirm you are not asking an L1 agent to reset another person's password. Manage Users is on the Ops Admin permission set only.

### Resolution

1. Retry the login at https://login.salesforce.com with the named username.
2. If the password is forgotten, stop. Ask the named Ops Admin to reset that user.
3. Do not create a shared login to get around a lockout.
4. Do not change a profile or a permission set from this page.

### Escalation Criteria

Escalate to Ops Admin when the login host and username are correct and the user still cannot log in, or when both CRM users are locked out.

## L1:MFA Problems

Keywords: authenticator code

### Symptom

The user reaches the password step and the authenticator code is rejected, or the user has no verification method on this device.

### Checks

1. Confirm the device clock is correct. A skewed clock rejects a time-based code.
2. Confirm the user is enrolling their own method. Do not accept a code sent by chat from another person.
3. Confirm nobody is asking to turn MFA off for the org or for one user. This runbook has no approved bypass.

### Resolution

1. Ask the user to retry with the device time set automatically.
2. If the code still fails, stop. Do not invent a temporary code, a backup code, or a profile change.
3. Ask Ops Admin to review the user's verification method. Ops Admin does that in the org. This assistant cannot.

### Escalation Criteria

Escalate to Ops Admin when a time check did not fix the code, or when anyone asks to disable MFA.

## L1:Record Visibility

Keywords: record visibility

### Symptom

A user cannot see a lead, opportunity, or case they expected to open.

### Checks

1. Confirm which persona group is assigned. Sales Rep has no case access. L1 has no lead or opportunity edit, and sees cases they own or that are in the L1 Support Queue. L2 can view all cases. Ops Admin can view all of the business objects.
2. Confirm the record owner and, for a case, whether it is in the L1 Support Queue or the L2 Escalation Queue.
3. Confirm User.Persona__c is only a Lightning label. It does not grant access. A blank persona does not make the user a Sales Rep or an agent.
4. The intended org-wide defaults are private for Lead, Opportunity, and Case, and public read only for Account and Contact. Those defaults are not deployed yet. Visibility today follows the permission set and the owner.

### Resolution

1. If the user should not see that object, explain the contract and stop. Do not grant View All or Modify All Data.
2. If the case should be in the L1 queue, confirm Ops Admin added the user to the public group Support_L1. The permission set group does not add queue membership.
3. If an L1 user needs a case they do not own and it is not in the L1 queue, they do not take it. Use case reassignment.

### Escalation Criteria

Escalate to Support Lead L2 when the case is escalated or in the L2 queue. Escalate to Ops Admin when the permission set group or the public group is wrong.

## L1:Missing Data

Keywords: missing data

### Symptom

A list or report looks empty, or a record the user just created is not where they expected it.

### Checks

1. Confirm the list is filtered to the owner's records. A Sales Rep does not see another rep's opportunities.
2. Confirm the synthetic dataset has not been loaded. Empty orgs are expected. The hand counts in the metric notes apply only after that load.
3. Confirm the four flows are Draft. Lead Assignment and Case Assignment do not move the owner while they are Draft. The creator remains the owner.
4. Confirm nobody deleted the record to hide it. Sales Rep and L1 have no delete permission on their objects. L2 has no case delete.

### Resolution

1. Clear list filters and search by the record name the user saved.
2. If the record is owned by the creator, tell the user that routing has not run because the flow is Draft.
3. Do not load data, activate a flow, or delete rows from this page.

### Escalation Criteria

Escalate to Ops Admin when a record was saved, the user has access to that object, and a name search still cannot find it.

## L1:Report Access

Keywords: cannot run reports

### Symptom

A user cannot run a report, or an L1 agent is asking for the all-team case backlog.

### Checks

1. Confirm the permission set group. Sales Rep includes Run Reports through Reporting_Sales. Support Lead L2 includes Run Reports through Reporting_Support. Ops Admin includes report administration through Reporting_Admin. Support Agent L1 has no reporting permission set.
2. Confirm the report folder. Pipeline By Stage is the sales report scoped to the running user. Cases By Status is the L2 backlog, grouped by status and priority.
3. Confirm L1 is not a consumer of the all-team support report. That exclusion is the requirement, not a broken folder.

### Resolution

1. If the user is L1 and wants the team backlog, explain that L2 runs it. Do not add Run Reports to the L1 group.
2. If a Sales Rep or L2 user should have Run Reports and the group is missing, stop. Ops Admin assigns the group.
3. Do not clone the Ops Admin permission set to fix a missing report.

### Escalation Criteria

Escalate to Ops Admin when a Sales Rep or Support Lead L2 has the correct group and still cannot run a report in their folder.

## L1:Dashboard Access

Keywords: cannot open the dashboard

### Symptom

A user cannot open Sales Dashboard or Support Dashboard, or the dashboard opens and looks empty.

### Checks

1. Use the same group check as report access. Without Run Reports, the user cannot open the dashboard. Public read-only folders do not override that.
2. Confirm the dashboard runs as the logged-in user. Pipeline By Stage shows that user's own opportunities. A Sales Rep should not expect the full-book 221,000 figure.
3. Confirm no synthetic load has been run. Empty charts are expected before that load. The metric notes still say the dashboard value was not observed.
4. Confirm the user is not L1 asking for Support Dashboard. L1 is not the audience.

### Resolution

1. For a missing Run Reports permission, follow the report-access resolution. Do not change the folder share from this page.
2. For an empty dashboard, confirm whether the user can see the underlying records. If they cannot, the chart is empty because of sharing, not because the dashboard failed.
3. Do not edit a dashboard component to force a number.

### Escalation Criteria

Escalate to Support Lead L2 for a support-metric question, and to Ops Admin when a user with the correct group cannot open the dashboard at all.

## L1:Case Reassignment

Keywords: case reassignment

### Symptom

A case needs a different owner, or an agent is trying to take a case they do not own.

### Checks

1. Confirm whether the case is owned by the asking user, in the L1 Support Queue, or in the L2 Escalation Queue.
2. Confirm L1 does not have Transfer Cases. Support Lead L2 does.
3. Confirm queue membership is the public group Support_L1 or Support_L2, not the permission set group.
4. Confirm a manual escalation still needs an escalation reason and Escalated By before the status can be Escalated.

### Resolution

1. If the case is in the L1 Support Queue and the user is in the public group Support_L1, they may take ownership from that queue.
2. If the case is owned by someone else and is not in that queue, L1 does not transfer it.
3. Ask Support Lead L2 to transfer it, or to take it from the L2 Escalation Queue.
4. Do not delete the case and recreate it to change the owner.

### Escalation Criteria

Escalate to Support Lead L2 for any transfer L1 cannot perform. Escalate to Ops Admin when the user should be in the public group and is not.
